# 交互地图产物标准

## 地图目标

地图帮助旅行者看懂全程、安排某一天、理解地点、保存选择并请 Codex 正式重排。候选池可以丰富，每日路线必须克制。

## Core 必备能力

- 真实地图和地点标记。
- 全程总览、某一天和统一地点详情三级浏览。
- 每日路线卡片、连续日期栏和当天有序地点。
- 搜索、城市/区域、分类、优先级和行程归类筛选。
- 必去、优先去、顺路可去、留档、待复核、已预约等自然语言状态。
- 正式路线、当天候选和其他地点的视觉区分。
- 行程图层、地点分类图层及其刷新恢复。
- 缺少正式路线时的虚线顺序引导，并明确“顺序参考，不代表道路”。
- 普通修改立即保存、高影响修改确认、撤销上一步。
- 修改汇总、受影响日期、请 Codex 重新安排和复制反馈。
- 刷新恢复和移动端可用。
- 同日路线使用独立 44px 排序手柄、160ms 长按、插入线和边缘自动滚动；卡片正文打开详情，上移/下移保留为降级操作。

完整行为以 `core-interaction-contract.md` 和 `map-feature-contract.md` 为准。

## 路线边界

- 正式路线只使用经过路网计算或人工复核的 `routeGeometry`。
- 不把地点坐标直接连成穿街、越楼或跨水面的路线。
- 没有路径几何时显示编号地点和外部导航入口。
- 允许用非交互虚线连接当天编号顺序帮助扫读，但必须标为顺序参考，不能称为道路、步行路线或导航结果。
- 当天每两个相邻正式地点都必须有对应的移动说明；缺失时明确显示尚未复核，不使用直线距离自动估算。
- 午餐、回酒店、取行李和晚餐前移动如果会改变顺序，必须进入当天时间线或相邻移动说明。
- 用户修改后弱化原路线并标记“路线需要重新安排”；正式重排前不向新增地点画线。
- 相邻交通只使用已复核信息；没有可靠路网或时刻信息时明确保留待复核状态。

## 页面和语言

- 地图始终是主要信息表面，桌面宽度不少于页面的 45%。
- 地点详情只有一个完整信息表面，避免 popup、抽屉和列表重复同一套内容。
- 点击日期卡片直接进入当天视图，不再叠加功能重复的日期下拉框。
- 日期栏切换保留地图视野；桌面保留并排的当前详情，手机从详情切换日期后返回所选日期的当天路线；进入当天后默认隐藏其他日期地点，回到总览恢复完整分布。
- 页面可见内容遵循 `user-facing-language.md`，不显示内部实现术语。
- 手机首屏保留可操作地图；日期可以横向浏览，当天路线使用有明确高度边界的纵向滚动区以支持 6–10 个地点拖拽，不能出现无边界的双重纵向滚动陷阱。

## Core 之后的设计

先通过 Core 功能和浏览器验收，再建立目的地设计语言。已有明确设计系统的攻略可以并行进行，但不能让视觉实现阻塞或改写行程状态。

- Enhancement 可以增加同页图片、专题信息和更丰富资料入口。
- Visual 可以增加目的地色彩、标记、路线风格和高级地图表达。
- 视觉只能增强识别和信息层级，不能把地图做成海报、手账或装饰背景。

## 线上逻辑文档

在 `docs/online-logic/map.md` 记录当前代码实际行为：

- 数据来源和字段。
- 总览、日期和详情切换。
- 筛选与地点归类。
- 图层控制、当前日期聚焦、日期切换的视野与详情保持。
- 正式路线和顺序引导线的区别与降级条件。
- 正式路线几何和缺失时降级。
- 普通与高影响修改规则。
- 撤销、修改汇总和受影响日期。
- Codex 请求生成与复制失败处理。
- 状态保存、清洗和恢复。
- 浏览器桌面与手机验证结果。

只在实际实现后记录 Enhancement 和 Visual，不把需求草案写成线上事实。

## 验证要求

静态验证：

- 地点和每日路线数据可解析，引用存在且无重复。
- Core HTML 容器和本地脚本存在。
- JavaScript 语法通过。
- 共享的数据、设计与活动验证仍按相关范围适用，不因地图模板不同而跳过。
- 地图 HTML validator 按模板互斥路由；同一产物不要求、也不得同时运行两个 template-specific validator。
- 完整攻略基于 `assets/guide-template-europe-public/` 或它的派生地图时，运行 `validate-europe-derived-map.js`。
- 轻量低保真或内部原型基于 `assets/guide-template/` 时，运行 `validate-map-html.js`，并要求其 `coreMissing` 为空。

浏览器验证：

- 页面、真实底图、地点和正式路线正常加载。
- 总览、日期切换、当天排序和统一详情可用。
- 搜索与筛选可用。
- 普通修改、高影响确认、取消和撤销符合合同。
- 修改后原路线弱化，新增地点没有推测线路。
- Codex 请求完整，复制有成功或失败反馈。
- 刷新恢复有效，桌面和手机无重叠与横向溢出。
- console 无相关 error/warn。

没有实际浏览器验证时，必须明确说明只完成静态验证。
