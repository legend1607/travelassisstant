# 旅行地图 Core 交互合同

本合同定义公开母版 **Europe direct-copy interaction v1**。母版直接来自已经验收的欧洲地图交互壳，而不是另行实现的近似版本；页面数据和主题可以变化，行为与状态语义不能分叉。所有旅行者可见文字遵循 `user-facing-language.md`。

## 默认完整地图母版

完整攻略默认从 `assets/guide-template-europe-public/maps/` 复制整套地图目录。派生地图优先只替换单文件 HTML 中的 `PUBLIC_TRIP_DATA`、旅行者文案、独立 storage key 与平面设计变量，不重新设计基础交互，也不从私人地图复制数据块。

欧洲公开母版固定以下基础结构：

1. **全程总览**：同时看到旅行骨架、每日路线、完整地点速查、筛选和地图分布。
2. **某一天**：使用连续日期栏切换，显示当天有序地点、相邻交通、正式路线和顺路候选；为保持清晰，其他日期地点默认隐藏。桌面切换日期保留当前地点详情，手机在地点详情中切换日期时返回所选日期的当天路线；两端都保留地图视野，不强制重新缩放。
3. **统一地点详情**：地图标记、当天路线和地点速查打开同一详情区域，不复制多套完整 popup 或抽屉。
4. **修改与重排**：加入、移出、调整优先级和同日顺序后立即保存，并沿用欧洲地图的专用手柄拖拽、上下移动和日期下拉交互。

必须保留的行为：

- 从总览进入某一天，再进入地点详情，并能返回当天和总览。
- 连续日期切换不丢失筛选、修改和当前选择。
- 当天正式路线有顺序；酒店可以作为起终点但不占游玩编号。
- 顺路候选可以在当天列表中直接加入，已安排地点可以直接移出或通过日期下拉移动。
- 分类图层和行程图层可以独立开关并刷新恢复；选择某一天时行程图层自动恢复，打开地点时对应分类自动恢复。
- 没有合格道路几何时，可以用虚线连接当前编号顺序，但必须明确写为“顺序参考，不代表道路”，且不提供虚构里程或时间。
- 地点详情、优先级、日期归类和顺序刷新后恢复。
- 普通地点卡片左侧提供至少 44px 的排序手柄；卡片正文仍打开地点详情。按住 160ms 后进入拖动状态，拖动时显示唯一插入位置；手机路线列表接近顶部或底部 48px 时自动滚动该列表，最高每帧 14px。`pointercancel`、`Escape` 和未改变位置都不写入修改；上移/下移按钮继续作为无拖拽降级操作。

第一版不能删除或重命名母版要求的页面标识和核心行为。运行：

```bash
node scripts/validate-europe-derived-map.js <itinerary-map.html>
```

通过基础交互与浏览器验收后，可以在单文件 `<style>` 中调整配色、字体、地点标记、路线样式、圆角、阴影和目的地装饰；这些变化不得降低地图可读性或改变行程状态含义。

## 任务 1：看懂全程

总览同时提供每日路线、地点筛选和地图分布。旅行者能快速理解城市顺序、每天主题、主要地点和未安排候选，不需要先打开多个面板。

## 任务 2：安排某一天

进入某一天后显示连续日期栏、当天有序地点、相邻交通、正式路线和可选候选。住宿可以作为起终点，但不占游玩编号。日期切换不会丢失当前地点、筛选、图层和已保存修改，也不会为了切换日期强制改变用户正在看的地图视野。桌面可以继续并排显示当前地点详情；手机若正处于地点详情，则切换日期后返回当天路线，让所选日期产生明确的可见反馈。

第一次进入当天视图时，自动缩放只根据当天正式路线和当天已安排地点计算。顺路候选可以继续显示；其他日期地点默认隐藏，避免地图被无关地点淹没。之后用日期栏切换时保留用户当前视野。

## 任务 3：理解一个地点

地图标记、当天列表和地点速查打开同一个完整地点详情。详情至少包含：为什么去、怎么安排、注意事项、当前行程归类、优先级、官网或预约入口、外部地图和体验线索。

完整信息表面只能有一个。可以使用侧栏、底部面板或独立详情区；不强制重复制作完整 popup。

## 任务 4：修改并保存

以下修改沿用欧洲地图原交互并直接保存：

- 修改优先级。
- 把普通未安排地点加入同城且未满的一天。
- 调整同一天普通地点顺序。

同日排序改变的是游览先后，不改变优先级。松手后必须重新编号并保存一次撤销快照；受影响日期的旧相邻交通、规划估算和正式路线都视为待复核，不能继续呈现成新顺序的有效交通。

地图中的修改只代表旅行者选择，不代表正式路线已经合理；跨城市、固定预约或住宿变动应回到对话中让 Codex 正式复核。

## 状态转换

浏览状态：

```text
全程总览 -> 某一天 -> 地点详情
地点详情 -> 某一天 -> 全程总览
```

行程状态：

```text
正式路线 -> 用户修改并保存 -> 需要时交给 Codex 重新复核
```

没有经过路网计算或人工复核时，不得把地点坐标直线称为道路导航；公开母版只把虚线作为访问顺序提示。

## 状态恢复

刷新后恢复当前日期、地点详情、筛选、图层开关、优先级、日期归类和顺序。派生攻略必须使用独立 storage key，不能读取其他旅行状态。

## 固定 Core 与交互分叉

- 不变层：直接复制版的 DOM 层级、列表/详情/地图状态语义、编辑流程与 Leaflet vendor runtime。
- 可变层：`PUBLIC_TRIP_DATA`、旅行者文案、独立 storage key，以及不改变布局和状态的平面设计变量。
- 用户只要求视觉变化时，不建立分叉。
- 用户明确要求改变状态语义、浏览结构或编辑流程时，才创建 interaction fork，并单独记录差异规格、兼容边界和浏览器验证。

## Core / Enhancement / Visual

- **Core**：本合同四项任务、真实地图、路线边界、状态恢复、移动端可用和浏览器验收。
- **Enhancement**：同页图片、缩略图、专题信息、天气或预约辅助。缺失时可以提示，但不能阻塞 Core 交付。
- **Visual**：目的地设计语言、定制标记、路线风格和高级地图表达。只能增强信息层级，不能改变 Core 状态语义。

## 浏览器验收

桌面和手机至少验证：底图非空、总览与日期切换、统一地点详情、加入/移出、优先级、同日排序（含 6–10 个地点的边缘自动滚动）、取消拖拽、撤销、刷新恢复和 console 无相关错误。
