# 旅行地图功能合同

完整旅行地图首先满足 `core-interaction-contract.md`。功能按 Core、Enhancement 和 Visual 分层，基础交互通过后才增加图片和目的地视觉设计。

本文件可以使用内部字段名描述实现；旅行者可见页面必须按 `user-facing-language.md` 使用自然语言。

## 使用参考地图

用户提供历史线程、参考 HTML 或截图时，先读取参考页面和对应线上逻辑，列出已经存在的用户任务和信息字段。保留行为结果，不照搬布局、弹窗数量或地图技术。

## Core：全程总览

- 标题、旅行摘要、旅行日数、地点数和城市/区域数。
- 每日路线卡片：日期、城市、当天主题、摘要和 1-3 个主锚点。
- 地点搜索、城市/区域、类别、优先级和行程归类筛选。
- 真实地图、地点标记和正式路线。
- 正式路线必须来自提供的 `routeGeometry`；没有路径几何时只显示编号地点。
- 没有合格路径几何时可以绘制非交互虚线作为“顺序参考”，但它不代表道路，不得附带推测距离或时间。
- 地图提供行程图层和按地点类别分组的图层开关；开关状态刷新恢复。
- 用户改动后弱化原路线并提示“路线需要重新安排”，不绘制推测线路。

## Core：某一天

- 点击日期卡片进入当天视图，而不是叠加第二套日期筛选。
- 连续日期栏用于切换日期，并提供返回全程入口。
- 当天地点按顺序展示；住宿不参与游玩编号。
- 普通地点卡片左侧有至少 44px 的专用排序手柄，卡片正文仍打开详情。按住 160ms 后进入拖动，显示单一插入线；手机路线列表的顶部/底部 48px 支持最高每帧 14px 的渐进自动滚动。`pointercancel`、`Escape` 和原位松手不保存；上移/下移按钮保留。
- 相邻地点显示交通信息。只使用已复核的 `transitSegments`；没有时显示“这段移动尚未复核”，不能用坐标直线距离自动补出时间。
- 当天候选仍可在地图和列表中浏览，并能用行内 `＋` 加入；已安排普通地点能用行内 `−` 移出。
- 进入当天后聚焦当天已安排地点、当天候选和当前选中地点；其他日期地点默认隐藏，回到全程总览后恢复完整分布。
- 日期栏切换保留用户地图视野，不反复强制 fit bounds；桌面保留并排的当前地点详情，手机从地点详情切换日期后返回所选日期的当天路线。

## Core：地点详情

地图标记、当天列表和速查清单打开同一个完整信息表面。详情至少包含：

- 中文名、原名、城市、区域和类别。
- 当前优先级和行程归类。
- 为什么去：`note` 或 `whyWorthIt`。
- 怎么安排：`plan`。
- 注意事项：`tip`。
- 资料依据：有结构化来源时，在注意事项之后显示可展开的 `evidenceSources`；每条只使用 `title`、`url`、`type`、`role`、`language`、`supports`、`checkedAt`、`status` 八个公开字段。公开 URL 必须是规范化的 HTTP(S)、有 hostname 且不含 username/password，外链使用 `noopener noreferrer`。
- 官网或预约入口、Google Maps 或等价地图入口、体验线索入口。
- 修改优先级、加入某天、移出、移动日期和当天顺序控制。

`sourceIds` 是构建阶段的内部关联键，公开 `PUBLIC_TRIP_DATA`、地图 HTML 和旅行者可见详情不得保留或显示 raw `sourceIds`。构建器必须先解析所有 id；缺失来源或非 HTTP(S) 链接应使构建失败。旧地点只有非结构化 `source` 时可以作为兼容回退，但只要 `evidenceSources` 非空，就隐藏旧文本，避免同一结论展示两套资料口径。

完整地点详情只能有一个。地图 popup 可以省略；如果保留，只作为轻量定位提示，不能再复制一套完整详情。

## Core：修改、确认和撤销

- 普通优先级、同城未满日期的加入和同日排序立即保存。
- 高影响修改由统一影响面板确认，规则见 `core-interaction-contract.md`。
- 取消影响确认不产生修改。
- 每次提交后提供“撤销上一步”，并同步恢复修改记录和受影响日期。
- 页面说明修改只是旅行者选择，正式路线尚未重排。
- 同日顺序或日期归类改变后，原相邻交通说明和规划估算统一失效并显示“交通待复核”，直到 Codex 正式重排。

## Core：修改汇总和 Codex 请求

- 显示修改数量和受影响日期。
- 用自然语言列出优先级变化、加入、移出、移动和排序变化。
- 提供“请 Codex 重新安排”，生成一段可独立发送的完整请求。
- 提供复制与失败反馈。复制失败时保留可手动选择的完整文本。
- 静态页面不能假装已把请求发送给 Codex。

## Core：状态恢复

- 保存和恢复日期、地点详情、筛选、优先级、日期归类、顺序、修改记录和撤销快照。
- 恢复时先过滤非普通 assignment、已经不存在的日期、非有限整数 order、负数、普通地点的 0 与身份未知的 0；已知酒店/住宿基底可保留 0，合法未知未来地点只保留正整数。已知地点的 malformed override 删除后回退到合法 default。
- saved structure sanitation、event eligibility sanitation 与连续编号 normalization 必须按此顺序执行，并在任一环节改变状态时合并为一次持久化；不得清空其他有效用户修改或 history。
- 关闭详情后刷新不重新打开已关闭地点。

## Enhancement

以下功能按目的地和资料条件增加，不阻塞 Core 验收：

- 同页真实图片、缩略图和大图预览。
- 图片搜索线索和授权说明。
- 天气、潮汐、展览、预约难度或酒店专题信息。
- 小红书、Reddit 等更细的体验线索。

没有授权图片时使用外部图片搜索入口，不制作虚假占位照片。

## Visual

目的地设计语言和 design tokens 通过公开母版单文件 `<style>` 进入。Visual 可以改变颜色、标记、路线样式和信息权重，但不得：

- 另造一套行程状态。
- 隐藏 Core 控件或降低地图可读性。
- 用装饰性直线代替正式路径。
- 让视觉实现阻塞基础地图交付。

MapLibre、Three.js 或其他会替换公开母版运行时的表达，不再属于普通主题微调；只有用户明确要求改变交互时，才作为 interaction fork 单独设计和验收。

## 数据字段

地点建议包含：`id`、`name`、`name_zh`、`city`、`area`、`category`、`coords`、`priority`、`note`、`plan`、`tip`、`officialUrl`、`mapUrl`、`experienceUrl`。住宿可补 `hotelRationale` 和 `hotelTradeoffs`；餐饮可补 `mealRole` 和 `reservationDifficulty`。

每日路线建议包含：`id`、`date`、`title`、`city`、`summary`、`capacity`、`routeStops`、`candidates`、`routeGeometry` 和 `transitSegments`。

## 验证

静态验证检查交互壳、公开数据边界、脚本语法和用户语言。浏览器必须实际验证：页面加载、真实底图、三级浏览、筛选、统一详情、加入/移出、优先级、同日排序、6–10 个地点时的边缘自动滚动、取消拖拽、撤销、刷新恢复、移动端和 console。
