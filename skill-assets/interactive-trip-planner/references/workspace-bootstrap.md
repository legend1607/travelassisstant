# 工作区规则自举

旅行攻略任务需要本地规则，避免不同 Agent 随意生成目录、低配地图、跳过事实复核或覆盖已有产物。

## 开始前读取

1. 查当前目录和上级目录是否存在 `AGENTS.md`。
2. 存在多个时，遵循离目标文件最近的规则。
3. 用户当前明确要求优先于文件规则。
4. 先读已有规则再决定是否需要补充，不根据聊天记忆重建项目约定。

## 没有 AGENTS.md 时

只有同时满足以下条件时才创建：

- 当前任务要在旅行攻略工作区中长期创建或维护文件。
- 当前目录和上级目录均没有适用的 `AGENTS.md`。
- 当前目录不是其他类型项目，或用户已经同意初始化旅行工作区。

创建方式：

- 将 `assets/workspace-AGENTS-template.md` 复制到目标工作区根目录并命名为 `AGENTS.md`。
- 只复制通用规则；在“当前工作区补充”中按本地事实填写攻略入口和用户已确认偏好。
- 不把 skill 作者的个人路径、私人旅行信息、订单、真实班次或特定攻略名称写入新模板。
- 在对话中说明创建位置和用途。

## 已经存在 AGENTS.md 时

- 不得覆盖已有的 `AGENTS.md`，也不把模板全文追加到文件末尾。
- 先比较现有规则与当前 skill 的关键合同：六阶段流程、语言跟随、资料复核、候选数量、欧洲母版基础交互和验证。
- 没有冲突时直接遵循现有规则，不做格式整理。
- 规则缺失时只补最小必要段落；涉及项目定位、用户偏好或文件所有权时先说明修改内容。
- 规则冲突时以用户当前明确要求和离目标文件最近的规则为准，并指出冲突，不静默选择方便实现的一方。

## 模板与本地规则的边界

内置模板只保存所有用户都适用的旅行工作区规则。本地 `AGENTS.md` 可以额外保存：

- 当前攻略入口和实际目录。
- 用户已经确认、会长期复用的旅行偏好。
- 本地数据来源、维护方式和特殊验证命令。
- 当前地图的线上逻辑文档位置。

不要把这些本地内容反向复制进公开 skill 模板。

## 避免

- 没有规则文件时直接生成孤立 HTML。
- 在非旅行项目里擅自创建旅行规则。
- 用通用模板覆盖用户已有规则。
- 把完整 skill 文档复制进 `AGENTS.md`，造成重复和后续漂移。
- 把工作区规则只留在聊天里。
