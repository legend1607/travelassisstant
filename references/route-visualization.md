# 路线图生成方法论

将行程数据转换为 AI 生成的路线图、每日行程卡、封面海报和手机行程图。

## 核心原则

1. 严格分离三个层级：
   - **事实层：** 地点、日期、顺序、交通、方向、时长、住宿与活动。
   - **信息层：** 每张图片展示什么，以及信息的视觉层级。
   - **风格层：** 配色、字体、材质、插画、摄影与参考图影响。
2. 不得让风格参考改变路线事实或增加目的地。
3. 不得把某一条示例行程当成默认模板。
4. 除非用户明确要求拼图，否则每一种风格、尺寸和页面都生成一张独立图片。
5. 优先保证路线清晰；内容过多时先减少次要信息，不得缩小核心文字至不可读。

## 输入来源

融合后直接读取 `shared/route-schema.json`，无需手动标准化行程。Phase 1 已完成路线标准化和 AMap 路径规划验证。

## 图片类型

- **总览路线图：** 完整旅程、主要站点、天数与交通方式。
- **每日行程卡：** 每天或每个完整路段单独一张。
- **区域详情图：** 自驾、沿海、徒步、城市漫步或复杂换乘。
- **封面海报：** 标题、视觉焦点与简化路线。
- **手机行程卡：** 旅途中便于查看的紧凑日程。

用户要求多种图片类型时，默认分别生成。不得把封面、总览、每日安排和贴士硬塞进同一张图。

## 信息层级

按以下优先级组织内容：

1. 标题和旅行天数；
2. 路线顺序和箭头；
3. 日期、天数和交通；
4. 必须保留的路线约束；
5. 精选活动或亮点；
6. 可选备注、距离、住宿和贴士。

文字预算：
- 封面：标题加 3-6 个短标签；
- 总览：标题、主要站点和天数范围；
- 每日卡：天数、路线、交通、3-5 个亮点；
- 详情图：路段标题、节点、方向和线路。

## 提示词编译结构

每张图片分别使用以下结构：

```text
用途：信息图
图片类型：[总览图 / 每日卡 / 详情图 / 封面 / 手机卡]
主要任务：[这一张图片需要完成什么]
画布：[比例、背景和使用场景]
路线事实：[有序节点、日期、交通、方向、道路或线路]
信息层级：[标题、主标签、次标签]
视觉风格：[由风格模块拆解出的视觉属性]
字体：[类别、字号层级、语言和必须准确的短文字]
颜色与材质：[色板、强调色、纸张或印刷处理]
参考图作用：[仅风格 / 仅构图 / 编辑目标]
必须保持：[不可改变的路线事实与视觉元素]
避免：[错误方向、虚构地点、拥挤、不可读文字、多余文案、水印]
```

必须出现的图片文字使用引号标明，并保持简短。若文字密集或要求完全准确，优先生成干净的视觉底图，再使用确定性排版工具添加已核验文字。

## 生成并检查

检查原图和手机缩略图：
- 路线顺序是否与 route-schema.json 一致；
- 箭头是否与文字移动方向一致；
- 去程和返程是否容易区分；
- 必须出现的标签是否清晰且拼写正确；
- 模型是否擅自增加或删除站点；
- 地图是否在不声称虚假精度的前提下大致合理；
- 风格是否只改变视觉表现，没有改动内容；
- 是否为独立图片，而不是意外生成的拼图。

核心检查失败时，针对单一问题重新生成一次。如果文字仍不准确，使用确定性文字排版。

## 强制规则

- 不得虚构目的地、景点、日期、交通、距离或旅行时间。
- 不得颠倒去程和返程。
- 不得把多种风格合并到一张图中。
- 不得在图片中使用长段落。
- 不得为了装饰密度牺牲路线准确性。
- 使用抽象地图时，不得声称具有精确地理比例。
