# 行程规划方法论

## 输入收集

开始前必须明确：

- 出发地、目的地
- 日期范围、天数
- 人数、年龄段
- 主要交通方式（自驾/公共交通/步行/混合）
- 节奏偏好（紧凑/宽松）
- 餐饮预算（人均范围）
- 饮食限制（过敏/忌口/偏好）
- 住宿偏好（青旅/酒店/民宿）
- 体力上限（日步行数/排队容忍度）
- 喜欢/不喜欢的类型

## 核心流程

### Step 1：抽取硬约束

日期、航班（含航站楼）、酒店（含地址）、不可更改的预约。

### Step 2：愿望清单分组

把用户想去的地方分成四类：

- **城内轻松** — 公共交通可达，不需预约
- **需预约** — 有票务/时段限制
- **远郊** — 需要单独半天或一天
- **可路过** — 不专门去，路过顺便看

### Step 3：删高风险点

- 天数不够 → 删远郊
- 节假日拥挤 → 删或换时段
- 天气敏感（户外） → 标记，有备选
- 排队过长（>容忍度）→ 删或换时段

**明说删了什么和为什么。不端水。**

### Step 4：AMap 地理编码

```javascript
AMap.Geocoder.getLocation(address, (status, result) => {
  if (status === 'complete') {
    const { lng, lat } = result.geocodes[0].location;
  }
});
```

### Step 5：AMap 路径规划验证

根据交通方式选择：
- `AMap.Driving` — 自驾
- `AMap.Transfer` — 公共交通
- `AMap.Walking` — 步行

获取实际通行时间，用于排日程。

### Step 6：AMap 行政区查询

```javascript
new AMap.DistrictSearch({ level: 'district' }).search(city, (status, result) => {
  // 获取区列表，辅助按区域分组
});
```

### Step 7：按区域重组

一天一个主区域。不要跨区跳来跳去。

### Step 8：补餐饮

按当天区域给候选，每顿饭 2-3 个候选。餐厅是当天区域的补给点，不是路线锚点（除非预约餐/强目的餐）。

### Step 9：补票务交通

只查关键的：机场↔市区、跨城交通、需要预约的景点。

### Step 10：输出

1. 参考文档（Markdown 格式，含每日行程表）
2. `route-schema.json`（标准化数据，Phase 3 和 4 共用）

## 输出检查清单（HARD GATE）

Phase 1 完成后必须确认：

- [ ] 每天一个主区域，没有跨区跳跃
- [ ] 每天最多一个重预约点
- [ ] 餐饮候选在当天区域内
- [ ] 每个地点有坐标 [lng, lat]
- [ ] route-schema.json 已生成，每个 location 有 `verified` 字段
- [ ] 删掉的点已说明原因
- [ ] 预算汇总已列出

## 选点原则

- 行程越顺越好，不是越满越好
- 一天一个主区域，一天只放一个重预约点
- 餐厅默认是补给点，不是锚点
- 不要为了一家店反向规划半天路线
- 排队超过用户容忍度 → 删或换时段

## 用户交互格式：四拍

1. **Re-ground** — 复述用户当前情况和约束
2. **Simplify** — 把复杂选择简化为 2-3 个关键决策
3. **Recommend** — 给出明确推荐，说明理由
4. **Options** — 给备选方案，让用户选
