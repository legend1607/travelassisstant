# 多版本方案生成方法论

当用户需求存在多条可行路线（如坡向选择、交通方式组合、是否绕行风景公路），应并行生成多个版本供用户对比选择，而非只产出单一行程。

## 何时触发多版本

满足以下任一条件即应生成多版本：

- 路线存在互斥分支（如长白山南坡 vs 北坡，同一时间只能去一个）
- 交通方式可组合（全程自驾 vs 自驾+高铁+包车）
- 用户明确要求"多出几个方案"或"生成多个版本以供选择"
- 费用、里程、体力消耗差异显著影响决策

## 版本数量

默认 **2-4 个版本**。超过 4 个会导致选择困难，少于 2 个等于没选择。

## 版本命名

使用字母编号：方案A、方案B、方案C、方案D。每个版本应有：

| 字段 | 说明 | 示例 |
|------|------|------|
| `id` | 字母编号 | `"A"` |
| `name` | 完整名称 | `"A·全程自驾·北坡版"` |
| `color` | 主题色（用于地图和卡片） | `"#ff3b30"` |
| `icon` | Emoji 图标 | `"🍁"` |
| `stat` | 里程/时长/过路费摘要 | `"约1037km · 15h16m驾 · ¥377过路费"` |
| `transport` | 交通方式 | `"全程自驾"` 或 `"混合（自驾+高铁+包车）"` |
| `desc` | 一句话描述亮点和取舍 | |
| `cost_per_person` | 人均费用 | `"~¥2900/人"` |
| `days` | 每日行程数组（同 route-schema 格式） | |

## 路线验证（AMap REST API）

每个版本的每段驾驶路线**必须**通过高德 REST API 验证，不使用估算值。

读取 `references/amap-services.md` 的「REST API 路线验证」章节获取完整调用方法。

验证后写入 `drives` 数组：

```json
{
  "name": "二道白河→通化",
  "time": "3h19m",
  "dist": "254km",
  "toll": "¥88"
}
```

## 费用分摊模型

多版本对比时，费用计算必须公平透明。分为两类：

### 均摊项（按人数分摊）

- 租车费（含异地还车费）
- 油费（按 ~0.7 RMB/km 估算）
- 过路费
- 住宿费
- 餐饮费

### 个人项（不均摊，每人独立）

- 高铁票
- 机票
- 个人购物

### 计算公式

```
人均费用 = (均摊项总和 ÷ 人数) + 个人项费用
```

混合方案的均摊项更少（自驾天数少 → 租车/油费/过路费少），但个人项多了高铁票。需分别列清两项，让用户理解差异来源。

### stat 字段中的费用

`stat` 字段如果包含费用摘要（如 `"人均¥3000"`），必须与 `cost_per_person` 字段保持一致。**禁止** stat 写旧值、cost_per_person 写新值。

## 移动端独立 HTML

每个版本生成一个独立的 `mobile/plan-{id}.html` 文件，另生成一个 `mobile/overview.html` 总对比页。

### 独立性要求

- API 密钥**内嵌**在 HTML 中（`window._AMapSecurityConfig` / `window.AMAP_JSAPI_KEY` / `window.AMAP_REST_KEY`），不依赖外部 `env.js`
- 单文件即可在手机浏览器打开（通过文件传输、AirDrop 等）
- 无需启动本地服务器

### overview.html 功能

- 对比表格：方案/坡向/G331/交通/里程/人均
- 每个方案卡片可点击在地图上高亮该方案路线
- "查看详情"按钮跳转到对应 `plan-{id}.html`

### 事件隔离（HARD RULE）

当可点击的父元素内嵌套了 `<a>` 链接时，链接的 `onclick` **必须**添加：

```javascript
event.stopPropagation();
event.preventDefault();
window.location.href = 'target.html';
```

否则点击链接会冒泡触发父元素的 `onclick`（如切换地图方案），导致无法跳转。

## 自动化生成脚本

使用 Python 脚本统一生成所有文件，避免手动编辑出错。脚本应包含：

1. **清理阶段** — 删除旧 plan-*.html 和 overview.html
2. **生成阶段** — 遍历方案数据，用字符串替换（非 f-string）填充模板
3. **验证阶段** — 检查所有文件的 stat 与 cost_per_person 一致性、HTML 结构完整性、API 密钥内嵌

### 为何不用 f-string

HTML 模板中大量使用 JS 花括号 `{}`，Python f-string 会将其解释为表达式。使用 `str.replace("__PLACEHOLDER__", value)` 避免冲突。

## 文件结构

```
mobile/
├── overview.html      # 四版总对比（含对比表格 + 地图）
├── plan-a.html        # 方案A详情（含每日地图 + 行程列表）
├── plan-b.html        # 方案B详情
├── plan-c.html        # 方案C详情
└── plan-d.html        # 方案D详情
```

每个 plan-*.html 包含：
- 顶部状态栏（方案名 + 返回总对比链接）
- 全屏 AMap 地图（按天切换）
- 底部抽屉（日标签 + 地点列表 + 总览页）
- 总览页：方案数据/要求满足情况/每日概览/重要提醒/其他方案链接
